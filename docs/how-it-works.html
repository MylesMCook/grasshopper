Keep the few things worth keeping.

Grasshopper saves explicit preferences, accepted decisions, verified lessons, and short handoffs. It does not collect whole conversations. Your agents share one private memory service instead of writing separate local memory databases.

1. Say what to remember

Ask an agent to save a preference or decision. It records the source, where it applies, and a revision number.

2. Pick up elsewhere

A fresh agent loads your confirmed preferences and the memories that fit the current project and machine.

3. Correct it when things change

An explicit correction becomes the current version. You can still inspect or restore earlier versions.

For example

“Use bun in this repository” stays with that Git project. “Use npm in the other repository” stays there. A Windows-only path stays on Windows.

See what your agents can see.

Open the memory view to browse current memories. Choose a project or device to see why a record applies. The view reads the same service as your agents; it does not create another store. Connect once in your browser, then use Disconnect to forget that browser session.

The view shows active records. Ask an agent for an earlier revision or a full record when you need its history.

Run your own copy.

01

Start the private server

Use the release bundle to create a new SQLite database on a host you control. Keep its model files and token on that host.

02

Connect your agents

Install the small client on each machine. Point each one to the same authenticated service. Codex can use the Grasshopper marketplace plugin. Keep the shared memory policy in one AGENTS.md.

03

Try one real preference

Save something you explicitly want remembered. Open a fresh agent session in another project or on another machine and ask what it knows. Check the record in the view.

Private by design. Honest about proof.

The server needs a token for memory reads and writes. Project names keep memories from mixing; they are not access controls. Use a separate service or server-enforced boundary for restricted data. Keep secrets and full transcripts out of memory.

The current release has automated checks and recorded client and machine trials. The test record says exactly which behavior was observed, and which desktop and recovery checks remain open.
